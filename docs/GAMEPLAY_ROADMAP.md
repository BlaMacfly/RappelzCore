# Gameplay implementation roadmap

Updated **2026-10-31** after archived corpse-skill validation and ground-detail correction. Continue the existing implementation, retain original assets/databases and publish the server/client branches separately. This inventory distinguishes usable local gameplay from packet/data scaffolding. Full original-client interoperability and official Epic/patch identity remain unresolved.

| System | Present implementation | Remaining implementation / acceptance criterion |
|---|---|---|
| Authentication and lobby | Accounts, encrypted Rust login, realms, character creation/selection, existing persistence. | Original-client capture/profile verification, stronger session/duplicate-login recovery and parser robustness. |
| World and movement | One map, player/NPC/monster visibility, movement prediction, remaining-route snapshots and GM layer changes. Native range/layer regressions pass. | More maps, transitions, collision/pathfinding, nondefault movement/latency validation and allocation of actual instances. |
| Combat and progression | Provisional melee, monster pursuit/retaliation, kills, XP/JP/currency (JP saturates at i64 maximum), leveling, regeneration and automatic revival. Native two-client regressions pass. | Decode real BasicStat/Exp data, typed wide progression values, equipment/stat effects, attack speed/hit/crit/resistance formulas and simultaneous aggressors. Preserve historical XP/level fixtures. |
| Groups | Invitations/refusal/consent, eight-member temporary groups, leadership, exclusion/disband/departure, private chat, live roster/vitals and native/Lua UI. [37 native checks](PARTY_VALIDATION.md). | Shared XP/loot formulas, offline/reconnect persistence if required, raids and dungeon binding. Reconcile native extension/policy with original party protocol before compatibility claims. |
| Skills and job growth | Typed learning/private durable levels/K UI/Lua; 40 learning checks. Archived 3212 corpse targeting, concurrent consumption guard, unchanged respawn timing, private cooldowns and 48 [native corpse checks](SKILL_CORPSE_VALIDATION.md). | Other effects/targets/costs, cast-speed/state/equipment modifiers, passive stats, late-observer presentation, restart-persistent cooldowns and job growth/inherited trees. Exact original SFrame interoperability/resource priority remains unproven. |
| Quests | Quest/QuestLink resources and imported quest templates; quest-list structure exists but server currently sends an empty list. | NPC offer/accept/abandon, objective counters, prerequisites, completion/rewards exactly once and Rappelz progress persistence. Verify relogin and two-client reward/privacy boundaries. |
| Items, equipment and shops | Bag/equip/unequip, basic vendor transactions and item persistence. Ground drops are explicitly refused while ground loot is absent, retaining the item instead of silently erasing it. | Enforce full item restrictions, transactional swaps/commerce, stacks/splitting/counts, consumables, endurance, storage/warehouse and trade. Complete ground entities/ownership/pickup before enabling drops. Explicit item erasure remains a separate action. |
| Loot and economy | Provisional direct kill currency and DropGroup DBC data. | Weighted drop evaluation, actual ground-item entities, ownership/expiry/pickup, group distribution, accurate prices/rewards and transaction recovery. Native observers must see one item and only one successful pickup. |
| Pets, summons and taming | Creature/item resource fields and some shared entity scaffolding. | Taming outcomes, durable summon identity/stats/equipment, binding cards, summon/desummon, movement/AI, commands/skills/XP and UI. Never map these blindly into unrelated WoW pet tables. |
| Social systems | Local/global/whisper chat and actual private group chat. | Friends/ignore, guild creation/ranks/chat/storage, blocked/spam handling and persistence. Each route must prove privacy and permission checks. |
| Trade, mail and auctions | No complete gameplay transaction system. | Offer/accept/cancel with ownership/quantity/money validation and atomic commit; mail/auction persistence and recovery. Disconnect/race tests must prove no duplication or loss. |
| Crafting and enhancement | CombineRes/CreatureEnhance/EnhanceEffect/ItemEffectResource data available. | Typed recipe/effect loading, requirements, server-authoritative rolls, consuming materials and committing results atomically, client result display. |
| Death and resurrection | Automatic full-vital revival with synchronized observers and Lua death/alive events. | Verified manual resurrection/respawn choices, penalties, item/skill resurrection and checkpoint rules. Avoid guessing type semantics from packet length alone. |
| NPC services and content | Placed NPCs, dialogue and basic shops, GM teleport destinations. | Quest/job/pet/storage/crafting/travel services and scripted conditions from verified data, localization and content validation. |
| Instances, dungeons and PvP | Layer isolation and privileged phase changes are available. | Instance lifecycle/IDs/ownership/reset, party entry/exit, encounters, PvP/PK flags/restrictions and rewards. A GM layer command alone is not a dungeon system. |
| Rendering, animation and audio | Native x64 terrain/models/animation, original HUD resources, MPQ assets and basic music/sound. Ground blending density increased from 128² to 1024² with matched visual verification. | Water, sky/fog, effects/grass, attachment/lighting accuracy, combat/skill visuals/audio and fuller gameplay windows. Validate using supplied local assets. |
| Addons and input | Lua 5.1 VM, TOC/XML subset, events/state, native manager/reload and scoped SavedVariables. Party units/events and private learned skill/JP diagnostics are connected to real state. | Physical-keyboard checks, corrupt/multi-file-save recovery, image textures/fonts/tooltips/XML expansion and measured update callbacks; preserve execution limits. |
| Persistence and deployment | Existing three databases, backups, character/item settings and separate buildable Git histories. | Versioned Rappelz extension migrations where needed, transactions and recovery tests, configuration/session hardening. Never bootstrap/reimport an existing installation as an upgrade. |

The next implementation order is **extend verified casting/effects and job/progression data → quest lifecycle → ground loot/transactions → pets/summons → remaining social/content/instance systems**, with client UI and actual Lua events delivered alongside the server behavior. Prerequisite data/protocol uncertainty must be resolved before inventing official formulas or effects. Complete each slice with unit/integration tests, a native session when applicable, preserved-data comparisons and updates to both branches; keep partial subsystems explicitly partial.
